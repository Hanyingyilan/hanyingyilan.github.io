## P1 架構提案：靜態產生、單一內容來源與分層漸進增強

現況：index.html 同時包含政策資料、CSS、計算公式、核心互動與動畫。政策並未完整出現在初始 HTML，也沒有自動化檢查。部署為 GitHub Pages main:/。

### 選擇
採用零執行期框架的靜態產生方式：開發環境以 Node.js 標準函式庫生成並檢查 HTML；產出提交至儲存庫，保留目前 Pages 發布方式。不需要資料庫、伺服器或主機遷移。相比繼續手工維護 HTML/JS 重複內容，此方案可自動檢查一致性；相比完整前端框架，短期網站的依賴與維護負擔較小。

### 邊界
- content/policies.json：分類、既有篩選設定、23 筆政策、來源參照的單一資料來源；不改寫政治內容，不臆造來源或政策狀態。
- src/index.template.html、src/site.css：版面及樣式來源。
- scripts/build.mjs：驗證資料，產生 index.html 與瀏覽器使用的必要資料；--check 驗證提交產物未過期。只有允許清單內的公開資產可發布。
- assets/js：核心介面與選用功能分離；完整內容可在 JS 失敗時閱讀。保留 #six-*、照片、分享、影片及試算器行為。
- src/calculator.mjs：純計算函式與具名金額設定；畫面渲染獨立，後續與來源模型整合。
- tests：Node 原生測試負責資料、產物、網址和計算契約；瀏覽器 smoke test 負責互動、深連結與執行期錯誤。任何瀏覽器測試依賴僅用於開發並鎖定版本。

### 實作契約與失敗隔離
2026-11-01 檢視中的抽取草稿已有 `src/app.js` 與產物對照表，但仍把選用功能初始化放在核心渲染之前；抽成外部檔案本身尚未解決失敗隔離。

- 產生的 HTML 保留一份完整政策總覽，每筆使用唯一、穩定的政策錨點；包含原有標題、全部細節與 `ref`。篩選卡片與分類面板可作為額外互動視圖，但不得複製 DOM `id` 或移除這份總覽。不要以全域 `.js` 類別先隱藏內容，再期待初始化成功後補回。主標題有實際文字，裝飾字元不重複其無障礙名稱。
- 核心入口負責分類、篩選、細節、分享連結與 `#six-*` 導航；試算器介面可獨立初始化。貓、集章慶祝、音效、遊戲與圖片匯出採獨立選用入口，核心不得靜態依賴它們才能執行。可使用獨立 script/IIFE 與小型事件或回呼介面，無須引入框架或全面重寫。分類切換完成後才通知集章；缺少該功能時使用無操作回呼。
- 每個選用入口自行檢查 DOM/API，初始化失敗只停用該功能；事件處理、Promise 與動畫回呼內的失敗也必須局部處理。只在頂層包一個 `try/catch` 無法隔離非同步錯誤。Canvas 不可用時保留文字內容與可理解的替代提示；分享 API 不可用時保留連結或儲存提示。
- 政策資料缺失或核心腳本載入失敗時，總覽、來源、原生錨點仍可閱讀。生成所有六個 `six-*` 目標，使停用 JS 時也有合理的落點；有 JS 時保留原本開啟對應分類的行為。既有 `#clean`、`#money` 與相對資產路徑不變。

### 發布允許清單
產物對照表只限制生成器寫入哪些檔案，並不限制 Pages 從儲存庫根目錄發布什麼。維持 `main:/` 與 legacy Pages build，採「明確公開檔案清單＋Jekyll 排除設定＋一致性檢查」：

1. 在工具設定維護逐檔公開清單：首頁、三個預覽頁、實際使用的圖片與影片、生成的 CSS/JS，及 #4 加入的 robots/sitemap。`assets/` 或 `v/` 不代表其中任何新檔案都自動獲准發布。清單同時涵蓋由 JS 引用的輪播照片與匯出用 `portrait-cut.png`，不能只掃描 HTML 的 `src`。
2. #4 在根目錄加入 `_config.yml`，明確排除 `docs/`、`content/`、`src/`、`scripts/`、`tests/`、套件/測試設定與報告等非公開路徑。檢查每個受版本控制的檔案：必須在公開清單中，或被發布排除規則涵蓋；否則驗證失敗。公開資料夾內新增非公開檔案也要被發現。`.gitignore` 與 robots 並不是發布排除機制。
3. 不加入 `.nojekyll`，也不依賴未驗證的「排除全部再 include」技巧；Jekyll 的 include/exclude 優先序與版本有關，見 [Jekyll 官方設定說明](https://jekyllrb.com/docs/configuration/options/)。在 Pages 相容的 Jekyll 環境檢查 `_site` 檔案集合與公開清單一致；若本機工具不足，明確記錄此項未驗證，部署後確認排除檔案回應與資產可用性。這是發布邊界，不是機密資料保護；儲存庫仍維持公開安全的內容。

### 可驗證的交接條件
- #11：資料抽取與原版 `PL` 的 23 個 ID、標題、細節、來源文字完全一致；拒絕重複 ID、未知分類、遺失的直接及 JS 間接資產。兩次 build 逐位元組相同；`--check` 不寫檔，能偵測每種生成產物過期。破壞案例在暫存測試副本執行，不能污染工作樹。
- #1：以 HTML 結構驗證每個政策錨點唯一，文字存在可閱讀的元素中，不能只在 script/JSON 找到字串就算通過。Playwright 分別驗證停用 JS、阻擋政策資料/核心腳本、阻擋選用腳本，以及 Canvas 回傳 null/選用 API 失敗；前兩者保留完整資訊，後兩者還須保持分類、篩選、深連結與試算器可用。一般執行情境不得有未捕捉的應用程式錯誤。
- #2/#4：共用正式根網址，canonical/og:url 不含查詢或 fragment；分類分享保留六種既有 fragment。`/`、`/index.html`、`/?v=6` 的中繼資料一致，不能宣稱靜態 canonical 等同 HTTP redirect。sitemap 只列可索引的正式網址；預覽仍可抓取並帶 noindex。新增未分類的儲存庫檔案與遺漏公開資產均有失敗測試。
- #12：純函式明確定義非整數、非有限值、負數及超界值的拒絕/正規化契約；測試零值、95,200、723,200、各年齡組與月數 0/24。快速連續改值後，畫面與無障礙讀值須收斂到最後一次輸入；政策文字的數值與產生的標籤/金額設定有一致性檢查，避免只抽取公式卻留下多份可漂移的金額。
