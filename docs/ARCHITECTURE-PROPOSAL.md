## P1 架構提案：靜態產生、單一內容來源與分層漸進增強

現況：index.html 同時包含政策資料、CSS、計算公式、核心互動與動畫。政策並未完整出現在初始 HTML，也沒有自動化檢查。部署為 GitHub Pages main:/。

### 選擇
採用零執行期框架的靜態產生方式：開發環境以 Node.js 標準函式庫生成並檢查 HTML；產出提交至儲存庫，保留目前 Pages 發布方式。不需要資料庫、伺服器或主機遷移。相比繼續手工維護 HTML/JS 重複內容，此方案可自動檢查一致性；相比完整前端框架，短期網站的依賴與維護負擔較小。

### 邊界
- content/policies.json：分類、既有篩選設定、23 筆政策、來源參照的單一資料來源；不改寫政治內容，不臆造來源或政策狀態。
- src/index.template.html、src/site.css：版面及樣式來源。
- scripts/build.mjs：驗證資料，產生 index.html 與瀏覽器使用的必要資料；--check 驗證提交產物未過期。只有允許清單內的公開資產可發布。
- assets/js：核心介面與選用功能分離；完整內容可在 JS 失敗時閱讀。保留 #six-*、照片、分享、影片及試算器行為。
- src/calculator.mjs：純計算函式與具名金額設定；畫面渲染獨立，後續與來源模型整合。
- tests：Node 原生測試負責資料、產物、網址和計算契約；瀏覽器 smoke test 負責互動、深連結與執行期錯誤。任何瀏覽器測試依賴僅用於開發並鎖定版本。

### 未來相容性
